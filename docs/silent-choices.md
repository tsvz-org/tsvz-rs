# Where tsvz-spec-v1 is silent

tsvz-rs follows `tsvz-spec-v1.md` wherever it decides. Where it leaves a choice open, tsvz-rs
does what TSVZ.py does, so the two tools agree in practice. Each choice is listed here with the
TSVZ.py code it copies. The differential harness (`difftest/`) finds new ones.

| Choice | tsvz-rs (as TSVZ.py) | TSVZ.py reference |
|---|---|---|
| `parts` ordinal | Printed as written in the file name (`002`, `B`), not normalized | `_partRows` |
| xz parts | A member may be an `.xz` stream or a legacy `.lzma` stream (auto-detected) | `lzma.LZMADecompressor()` |
| xz stream padding | Zero bytes after an xz stream are judged a member cut short (a warning; every line is read, under any policy) | `decompress_items` |
| zstd skippable frames | Decoded as frames with no output | `ZstdDecompressor` |
| A corrupt member's output (`recover`) | What its bytes decode, fed one at a time, before the byte that fails; what that byte decodes is dropped with it | `_decodeAlone` |
| Row width | Rows, and a missing key's defaults, padded to the store's width (§3.6 lets a reader pad): the count of the defaults active at the first data row when there are any, else that row's written cells. A longer row keeps every cell | `_specPadRow` |
| Appending after a torn tail | The uncommitted bytes after the last newline are cut first, with a warning, so the new record cannot join them | `_lockedAppend(…, 'truncate')` |
| `scrub` markers | `#_version_#` written as `1`; then strip, fill-empty, return-defaults, rotate, write-ack, member-size and on-corruption when not default; `#_defaults_#` last | `_specPreamble` |
| `scrub` rows | Fully resolved, padded with empty cells to the final defaults' width; the §19.4 compensating layout only when a row would not read back the same | `_specScrubCells`, `_specRoundTrips` |
| `scrub` and checksum markers | Not kept: a snapshot has no segments to verify | `_specScrub` |
| `scrub` of a multi-part store (§19.2, §19.8; TSVZ.py refuses it) | The parts before the active one (no writer appends to them, §17.7) become a new part between them and the active one, its ordinal the midpoint of the free ones, spelled with the active ordinal's width and case (never 0, §17.1); with no ordinal free, they are compacted in place into the last of them (§19.8), with a warning. Then `#_rotate_#` applies to them, newest first: `rename` adds `.rotated` before the codec suffix (part 0 becomes `s.tsvz.0.rotated`), a rename cut short is finished by the next scrub, and `delete` becomes `rename` after recovered damage. Writers are never paused | — |
| When a multi-part scrub writes nothing | When the last part before the active one already reads alone as all of them, is no larger than a new snapshot, and begins with `#_snapshot_#` when other parts precede it: a scrub run again (by cron, say) adds no copy each time, and only finishes a rotation cut short. Without hard links (FAT, some network and FUSE mounts) a multi-part scrub compacts in place, with a warning | — |
| What a snapshot part holds | After the header comment, `#_snapshot_#` whenever other parts precede the part (§19.2.3e, §19.10.2). Under `#_rotate_# keep`, the §19.2.3 snapshot; under `rename` or `delete`, and when compacting in place into a part that others precede, one that states every stateful marker and deletes every key those parts leave live, so that it reads as the whole prefix alone, after those parts, and after any first ones of them | — |
| Where a read begins (§19.10.3) | At the last snapshot part (never part 0), as TSVZ.py 4.9 does: the parts before it are not read, but a change to one reloads the store. A bzip2 part is not looked at: it gives nothing before a whole block, so the look costs a block's decode that the read repeats (1.3 to 1.9 times 0.1.3's time on a store with no snapshot part, 2026-11-16), and a reader may begin there but need not (§19.10.3): a bzip2 snapshot part is read like any part, and the result is the same. `verify`, and the reads `scrub` and `clear` decide from (`Options::full_history`), replay every part (§19.10.4) | `_specSnapshotStart`, `_specLoadOnce` |
| Telling a compressed snapshot part | From its first lines, read a piece at a time until they come out of members that passed their checks (bzip2 gives nothing before a whole block); a member cut short or corrupt before the marker makes it none | `_specIsSnapshotPart` |
| `#_snapshot_#` given to a writer | Refused in a strict store (`set`, the handler, `Writer::append` and `append_payload`; exit 1, nothing written): as the first line of a part it would make readers skip the parts before it. In a loose file it is a comment, and written | `_specFormatRecord` |
| A multi-part scrub of parts that cannot be read whole, or that hold checksum segments | Refused, nothing written: a snapshot of a partial read would hide the rest from later readers, and a checksum segment open into the active part would no longer verify | — |
| An integer marker value too large for 64 bits (`#_version_#`, `#_member_size_#`) | Still an integer (§12.4): the largest 64-bit value, so a version above every one implemented, and a member size beyond any part (TSVZ.py 4.8 does so for `#_version_#`; a member size it cannot convert is ignored) | `_specApplyMarker` |
| How a snapshot is written | A new part is written beside the parts to `<stem>.snapshot-<time>-<pid>-<n>.<ext>[.<codec>]` (a process killed meanwhile leaves it there, and it is no part), synced, checked to read as the parts it holds (alone and after all of them), then hard-linked under its name (a link never replaces a file) and the directory synced; it takes the owner of the last part it holds and a mode no more open than any of them, but its owner reads and writes it. In place, the new content first goes to a private recovery copy, `<part>.scrub-<time>-<pid>-<n>.<ext>` (for a multi-part store, checked the same way), then over the part (space reserved first, and its mode set just before and put back only if the part surely holds its old bytes), and the copy is removed unless the rewrite left the part damaged; the part keeps its owner and its owner's read and write bits, and its other bits become the intersection of those of every part it holds rows of, without group access unless they all share its group. A one-part scrub with no room for the copy rewrites without one, with a warning, where the file system overwrites in place (ext2/3/4, XFS, f2fs, tmpfs); elsewhere it refuses. TSVZ.py never writes a `.scrub-` recovery copy (it writes `.damaged-` backups). Rows never go to a part whose owner could not read every part they come from: the scrub is refused | — |
| `clear` of one part | Header comment and markers, without `#_version_#` | `_specClearTabularFile` |
| A path that names one part (`s.tsvz.1`, §20.1.3) | `clear` and `scrub` refuse it, exit 1, nothing written; other operations treat it as a store of its own | `_specClearTabularFile`, `_specScrub` |
| Space for an in-place rewrite | Reserved first with `posix_fallocate` on Linux (§19.8's SHOULD); if a write still fails, the whole old part is put back, and if that fails too the error says the part is damaged. macOS has the restore only | `_specRewriteInPlace` |
| A damaged part before a rewrite | Copied to `<part>.damaged-<YYYYmmddTHHMMSS>` (`.1`, `.2`, … when taken) and synced | `_specBackupPart` |
| The backup copy's permissions | The part's read bits plus owner write (`mode & 0o644`, less the umask), so a private store's copy stays private and never carries setuid, setgid or execute bits; the part's owner and group where allowed, else, left in another group, no group bits | `_specBackupPart`, `_matchOwner` |
| A gzip member header | Parsed a byte at a time with no length cap, as zlib accepts it | `zlib.decompressobj(31)` |
| xz and lzma decoder memory | At most 1 GiB; a member whose header demands more (a legacy `.lzma` header can declare a 4 GiB dictionary) is judged corrupt. TSVZ.py's `lzma` has no limit | `lzma.LZMADecompressor()` |
| The table format | `pretty_format_table`: rows never shortened; `verify`/`parts` fitted to the terminal; control characters escaped | `_cliEmitRows`, `_cliEmitFields`, `_cliTableCells` |
| Long options | A unique prefix is accepted (`--delim`), as argparse did | `_cliParseArgs` |
| `setdefault` with a marker key | Usage error (2), as §21.7.3 asks of a handler | `_ServeStore` |
| Bulk input | Lines with an empty key are skipped (a reader would ignore them) | `_cliStdinBatch` |
| A part that cannot be read | Skipped with a warning: reads print what was read and exit 1 (§21.8.5 for a handler, and the same on the files so that routing changes nothing); `pop`, `popitem`, `setdefault`, `clear`, `scrub` and a `delete` that must name a key (§20.2.7) change nothing | `_specLoad` (`'unreadable'`) |
| `--x-written` | A handler accepts it: the write is answered once written, and a failed write answers status 1. A routed `set`, `append` or `delete` sends it, so that a failed write exits 1 as on the files; so does every write of `handler::Client` | `_serveDispatch`, `_cliRouted`, `TSVZClient` |
| Routed operations | Every operation but `serve`, `stop`, `verify` and `parts` (which read the files themselves) | `_cliHandler` |
| A routed operation whose handler goes away | `read`, `get`, `has`, `len`, `keys` warn and run on the files; any other exits 1, saying it may or may not have been applied | `_cliRouted` |
| Handler statuses | A reading operation on a missing store: 1, "no such store"; a read that skipped a part or stopped: 1, "could not read every part of the store", with what was read | `_serveDispatch` |
| `pop`, `popitem`, `setdefault` through a handler | Answered once their write is made; a failed write answers 1 and no row | `_ServeStore.pop` |
| Writes that fail after they were acknowledged | Reported on `serve`'s standard error; every response carries a `#!` warning until a batch is written again | `_ServeWriter`, `_serveRespond` |
| The handler's socket | A new `tsvz-XXXXXX` directory under `$XDG_RUNTIME_DIR` when it is absolute and writable and access is private, else the temporary directory, made absolute; socket 0600, 0660 with `--x-group`, or `--x-mode`; the directory 0700 plus search bits for whom the socket admits | `_ServeHandle.start` |
| The pointer file | Created 0600, published 0644; one that is incomplete is read again after 50 ms; one with another first line, or no `address` or `host`, means no handler, without a warning | `_ServeHandle.lock`, `_serveLookup` |
| Request line limit | 64 MiB; a longer line closes the connection | `_SERVE_LINE_LIMIT` |
| `stop STORE` | After `#0`, waits up to 10 s until the pointer file no longer names that handler | `_cliStop` |
| `serve` options | `--x-idle-timeout S`, `--x-group G`, `--x-mode M`, and `--x-direct` for any command, spelled as TSVZ.py spells them | `_CLI_OPTIONS` |
| `-v` with a handler | A routed command names the handler it used; `serve -v` reports each request's status | — |
| Strict stores only (departs from TSVZ.py) | `serve` refuses a loose file and the CLI never forwards one: TSVZ.py applies its 3.39 rules on top of what both read alike (below), so a forwarded command could print what the other tool's files would not | — |
| Loose files | Lines split on the delimiter, with no markers, escaping or stripping (§5.2, §20.2.4: a loose file's data semantics are implementation-defined). As TSVZ.py reads them: the NULs at the start of a line are dropped; line 1's byte-order mark is part of its key; the first keyed line (not empty, no comment but a `#_defaults_#` line, a key that is not blank) sets the column count; a key alone, or with only blank cells, is a deletion, but a row in a one-column file; a row longer than the column count is read whole, but for the empty cells at its end, which TSVZ.py cuts (TSVZ.py from 5.5); a first cell that is `#_defaults_#`, without the whitespace at its end, makes a defaults line, and a key that only begins with it is a key. Unlike TSVZ.py, tsvz-rs reads `#_defaults_#` lines as comments (so it fills no empty cell from them, and a bare one in a one-column file is no row), strips and decodes no key or cell (a cell keeps its trailing whitespace), reads a line whose key is only whitespace as a row (TSVZ.py skips it), keeps the empty cells at the end of a row longer than the column count that TSVZ.py cuts, keeps a run of CRs after the first, and ignores an unterminated last line, which TSVZ.py reads (docs/limitations.md). Rows are padded to the width of the first keyed line, a deletion's included, as TSVZ.py's default pads them | `_processLine` |
| Loose files rewritten | `scrub` keeps each line it keeps as the file has it (a CRLF line stays one): line 1, every `#_defaults_#` line, the lines that set the column count, and each live key's first and last line, the last taking the first one's place (never line 1's) where no `#_defaults_#` line lies between them and the column count stays; so tsvz-rs, and TSVZ.py given no header, read the file as before (but for a byte-order mark that an unterminated first line loses, docs/limitations.md). Only lines no read depends on go (comments, empty lines, lines with an empty key, superseded rows and the rows of dead keys), and a file with a line the two read differently (whitespace at the end of its key, a `<` in its key, a NUL or CR in the line) loses nothing else. `clear` keeps line 1 when it is a comment or empty and, in a file of more than one column, the `#_defaults_#` lines in force, with a `#_defaults_#` line of blank cells at the file's column count before them when the first has another count, so that rows written later read to TSVZ.py with the defaults they had; a one-column file keeps none (a defaults line has more cells, and would make a key alone a deletion), so rows written there later read without the defaults they had. TSVZ.py's own clear drops them all | `_legacyScrub`, `_legacyCompactPlan` |
| A delete in a loose file | Decides from the file's column count alone, reading only as far as its first keyed line. More than one column: writes a key alone for each key asked, live or not, without the whitespace at its end, as TSVZ.py reads a key (it writes the key as given) and, where that differs, as given, since tsvz-rs reads a key whole; a key of only whitespace is written as given only (tsvz-rs reads such a row, and TSVZ.py skips it). No keyed line yet: nothing (it would set one column, and be a row). In a one-column file, where nothing can delete, `delete`, `pop` and `popitem` rewrite the file without the key's lines (a key is named without the whitespace at its end, so that a key of only whitespace takes every line whose key is only whitespace, and a reset of `#_defaults_#` writes nothing, there and where no line is keyed yet, since its line would be a row to TSVZ.py, a key the user never had); when the line that set the column count goes and the next keyed line is wider, the first remaining key, alone, takes its place (TSVZ.py puts the last key there, which moves that key first); with only `#_defaults_#` lines that hold a value left after the last key goes, the file becomes two-column, as TSVZ.py's own delete writes it. An unterminated last line is not seen when that key is picked (docs/limitations.md) | `_legacyDropLines` |
| When the parts are listed again | At every check of a store (a read through a handler, a write's check of other writers), except while the directory's change time shows no name changed: on a local kernel file system that sets it at every name made, renamed or removed (ext2/3/4, XFS, btrfs, ZFS, f2fs, tmpfs; APFS on macOS) whose change times are finer than a second, for the same directory (device and inode) with the same change time, at least 2 s old when last listed. Never on FUSE, network, overlay or unknown file systems, HFS+, or for a listing in which part 0 is a symbolic link. A writer checks, once it holds the lock, that no part was started since its listing (§17.7), by the same rule. A loose file's directory is never looked at | — |
| `-V` | `tsvz-rs` and the crate version (`tsvz-rs 0.1.4`) | — |
